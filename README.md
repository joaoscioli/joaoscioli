## About me

I focus on **Java and Spring Boot backend engineering**: REST APIs, domain modeling, persistence, security, and automated testing. I also explore how AI features fit into backend services, with attention to reliability, evaluation, and observability.

My repositories bring together implementation projects, experiments, and engineering notes. I use them to make both the code and the reasoning behind it easy to follow.

> I value systems that are understandable before they are clever.

## Selected projects

### [Subscription Billing API](https://github.com/joaoscioli/subscription-billing-api)
A backend portfolio project built around a SaaS billing domain: organizations, customers, plans, subscriptions, and cancellation. Developed incrementally, with an emphasis on domain constraints, database migrations, testing, and technical documentation.

**Focus:** Java · Spring Boot · REST APIs · PostgreSQL · Flyway

### [Spring AI Engineering Labs](https://github.com/joaoscioli/spring-ai-in-action-labs)
Practical experiments with AI features in Java backends. The Board Game Buddy application explores provider retries, fallback handling, and Micrometer metrics, with WireMock tests covering success and failure scenarios.

**Focus:** Spring AI · Resilience · Observability · Integration testing

### [Fraud Detection Rules Engine](https://github.com/joaoscioli/fraud-detection-rules-engine)
A compact Java project that models transaction risk through independent business rules. Decisions include a risk status, a total score, and explanations for triggered rules.

**Focus:** Java 21 · Domain modeling · Risk scoring · Explainable decisions

### [AI Agent Business Assistant Lab](https://github.com/joaoscioli/ai-agent-business-assistant-lab)
A learning and product lab exploring assistant workflows for small businesses: turning scattered information into structured briefings, documents, and useful workflows.

**Focus:** AI agents · Tool-based workflows · Software architecture · Product thinking

## How I build

- **Start with the domain.** Make business rules and API contracts explicit.
- **Work in small increments.** Keep changes focused and easy to review.
- **Test behavior.** Cover meaningful scenarios, including failures and recovery.
- **Document the decisions.** Explain the constraints, alternatives, and trade-offs.
- **Make projects approachable.** Aim for clear setup instructions and reproducible environments.
